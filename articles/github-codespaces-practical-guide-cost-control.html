GitHub Codespaces: بيئة تطوير سحابية مع إدارة الساعات والتخزين والتكلفةGitHub Codespaces: Cloud Development with Practical Cost Controls

تعرف إلى إنشاء Codespace من المستودع، وحساب الاستخدام المجاني والتكلفة، وإيقاف البيئة وإدارة التخزين والمنافذ والأسرار بأمان.Create a Codespace from a repository, understand included compute and storage, control billing, stop idle environments, and protect secrets and forwarded ports.

النسخة العربية

ما GitHub Codespaces؟

GitHub Codespaces بيئة تطوير تعمل على خادم بعيد وتفتح من المتصفح أو Visual Studio Code. بدلاً من تثبيت سلسلة الأدوات وقواعد التشغيل على كل جهاز، ينشئ GitHub مساحة عمل مرتبطة بمستودع أو فرع، وتعمل فيها الطرفية والمحرر وأدوات البناء داخل بيئة سحابية. هذا مفيد عندما تتنقل بين أجهزة مختلفة أو تريد بدء مشروع بسرعة من دون إعداد محلي طويل.

لكن كلمة «سحابي» لا تعني أنه مجاني بلا حدود أو أنه بديل كامل عن اتصال مستقر. يحتاج Codespaces إلى الإنترنت للوصول إلى مساحة العمل، ويستهلك وقت معالجة أثناء التشغيل ومساحة تخزين ما دام موجوداً. افهم دورة حياة البيئة وتكلفتها قبل إنشاء عدة نسخ للمشروع نفسه.

إنشاء مساحة عمل من مستودع

افتح المستودع على GitHub، ثم اختر Code وبعدها تبويب Codespaces وأنشئ Codespace على الفرع الذي تريد العمل عليه. إذا كان المشروع يضم ملف devcontainer.json، فسيستخدم GitHub إعداداته لبناء البيئة وتثبيت الأدوات؛ لذلك راجع محتواه قبل التشغيل، خصوصاً أوامر ما بعد الإنشاء التي قد تنفذ تلقائياً. لا تشغّل إعداداً من مستودع لا تثق بمصدره.

بعد فتح المحرر، افتح الطرفية ونفّذ اختبارات المشروع المعتادة، ثم استخدم Git لحفظ التغييرات ودفعها إلى الفرع. إذا كان التطبيق يعرض منفذاً محلياً، يظهر في لوحة Ports ويمكن فتح معاينة في المتصفح. ابدأ بمنفذ خاص؛ لا تجعل المعاينة عامة لمجرد أن ذلك أسهل، لأن الرابط العام قد يسمح لأي شخص على الإنترنت بالوصول إلى الخدمة.

الاستخدام المضمّن: ساعات المعالجة والتخزين

تذكر صفحة الفوترة أن الحساب الشخصي المجاني يتضمن حالياً 120 ساعة من وقت المعالجة شهرياً و15 غيغابايت-شهراً من التخزين، بينما يعرض GitHub Pro مقدار 180 ساعة و20 غيغابايت-شهراً. هذه الحصة للحسابات الشخصية؛ خطط المؤسسات والشركات لا تحصل على الحصة المجانية نفسها. وعند استنفادها قد يتوقف إنشاء أو استئناف البيئات القابلة للفوترة ما لم تكن إعدادات الدفع والميزانية تسمح بذلك.

لا تساوِ ساعات المعالجة بساعات الساعة الحائطية لكل نوع جهاز. توضح وثائق GitHub أن الاستهلاك يحسب بوحدات تتأثر بعدد الأنوية؛ فآلة ذات نواتين تستخدم مضاعف 2 لكل ساعة نشطة، وآلة ذات أربع أنوية مضاعف 4. لذلك يمكن أن تستهلك آلة أكبر الحصة أسرع حتى لو تركتها تعمل للمدة الزمنية نفسها.

الأسعار بعد الحصة المجانية

تعرض صفحة GitHub الرسمية وقت المراجعة سعراً قدره 0.18 دولار لكل ساعة لآلة ذات نواتين، و0.36 لأربع أنوية، و0.72 لثماني أنوية، و1.44 لست عشرة نواة، و2.88 لاثنتين وثلاثين نواة. ويعرض التخزين 0.07 دولار لكل غيغابايت-شهر. هذه أسعار القائمة المنشورة بالدولار؛ راجع صفحة الفوترة والحاسبة لأن الضرائب وسياسات الحساب والتغييرات المستقبلية قد تؤثر في المبلغ النهائي.

مثال حسابي مبسط: تشغيل آلة ذات نواتين عشر ساعات يكلف 1.80 دولار قبل احتساب الحصة المضمّنة، بينما عشر ساعات على أربع أنوية تساوي 3.60 دولار. لا تنس التخزين؛ البيئة المتوقفة لا تستهلك وقت معالجة أثناء التوقف، لكنها تظل تستهلك مساحة تخزين إلى أن تحذفها. إذا أنشأت بيئات كثيرة ثم نسيتها، فقد تكون كلفة التخزين هي المفاجأة.

أوقف البيئة ولا تكتف بإغلاق تبويب المتصفح

الافتراضي في Codespaces هو إيقاف البيئة بعد 30 دقيقة من عدم النشاط، ويمكن تغيير مهلة الخمول. كما تذكر وثائق دورة الحياة حداً أقصى لعمر البيئة يبلغ 12 ساعة قبل إيقافها تلقائياً. إغلاق تبويب المتصفح لا يوقف Codespace فوراً؛ فقد تستمر العمليات حتى تنتهي مهلة الخمول. لذلك أوقف البيئة يدوياً من قائمة Codespaces عندما تنتهي من العمل.

البيئات المتوقفة قد تُحذف تلقائياً بعد 30 يوماً من عدم النشاط وفق الإعداد الافتراضي، ويمكن تغيير فترة الاحتفاظ. احفظ تغييراتك وادفعها إلى Git قبل حذف مساحة لم تعد تحتاجها. حذف البيئة يبطئ تراكم التخزين مستقبلاً، لكنه لا يمحو بالضرورة الاستخدام الذي تراكم بالفعل خلال دورة الفوترة الحالية.

الأمان: الأسرار والمستودعات والمنافذ

تعمل كل Codespace على آلة افتراضية وشبكة معزولة بحسب وثائق GitHub، لكن صلاحيات الرمز الممنوح للبيئة تتأثر بصلاحيتك على المستودع. إذا كان لديك إذن كتابة، فقد يحصل الرمز على قراءة وكتابة للمستودع. لذلك لا تفتح مستودعات مجهولة، ولا تنفذ سكربتات تهيئة قبل مراجعتها، ولا تضع مفاتيح API أو كلمات مرور داخل ملفات الإعداد أو الشيفرة.

استخدم Codespaces Secrets لتخزين القيم الحساسة، وحدد نطاق المستودعات التي يمكنها استخدامها. جميع المنافذ المحوّلة خاصة افتراضياً، لكن جعل منفذ عاماً يعني أن أي شخص على الإنترنت يستطيع الوصول إليه من دون تسجيل دخول GitHub. قبل تغيير Visibility إلى Public، تأكد من أن الخدمة لا تعرض لوحة إدارة أو بيانات اختبار أو واجهة داخلية.

خطة عملية لتقليل التكلفة

اختر أصغر نوع آلة يكفي للمهمة، واستخدم الصورة الافتراضية عندما تلبي احتياجات المشروع، وقلل الإضافات والملفات الكبيرة التي تستهلك التخزين. راجع صفحة الاستخدام والفوترة دورياً، واضبط ميزانية تنبهك قبل تجاوز الحد. أوقف Codespace بعد انتهاء الجلسة، واحذف النسخ المؤقتة التي لم تعد تحتاجها، وقلل فترة الاحتفاظ إذا كنت تنشئ بيئات كثيرة للتجارب.

إذا كان اتصالك متقطعاً، ادفع التغييرات إلى Git على فترات قصيرة؛ فـ Codespaces بيئة سحابية ولا يمكنك متابعة العمل فيها بلا اتصال. احتفظ بنسخة محلية أو استخدم حاوية تطوير محلية عند الحاجة إلى العمل دون إنترنت. الاختيار الجيد ليس تشغيل أقوى آلة، بل إنشاء بيئة مناسبة للمهمة وإيقافها ومراجعة تكلفتها بوعي.

متى يكون Codespaces مناسباً؟

يناسب Codespaces المراجعات السريعة، ومساهمات المشاريع المفتوحة، وتجربة فرع جديد، والعمل من جهاز لا تريد تثبيت أدوات عليه، أو توفير بيئة متطابقة لفريق. لكنه قد لا يكون الخيار الأفضل لمعالجة ثقيلة مستمرة أو اتصال إنترنت غير مستقر أو مشروع يتطلب وصولاً محلياً إلى أجهزة ومنافذ لا يمكن توفيرها في بيئة سحابية.

قبل الاعتماد عليه، اختبر مستودعاً صغيراً، وافحص إعداد devcontainer، وراقب الاستهلاك، وتأكد من أن الأسرار والمنافذ مضبوطة على الحد الأدنى. إذا كانت التكلفة أو الاتصال غير مناسبين، استخدم GitHub لإدارة الشيفرة مع بيئة محلية أو حاوية تطوير. الخدمة أداة إنتاجية عندما تُدار، وليست مساحة عمل ينبغي تركها مفتوحة بلا مراقبة.

English edition

What GitHub Codespaces is

GitHub Codespaces is a development environment hosted remotely and opened through a browser or Visual Studio Code. Instead of installing every toolchain and dependency on each device, GitHub creates a workspace linked to a repository or branch, with a terminal, editor, and build tools running in the cloud. This is useful when you move between devices or want to start a project without a long local setup.

Cloud-based does not mean unlimited free use or independence from a reliable connection. Codespaces needs internet access, consumes compute time while running, and uses storage for as long as the environment exists. Understand the lifecycle and billing model before creating several copies of the same project.

Create a workspace from a repository

Open a repository on GitHub, choose Code, select the Codespaces tab, and create a Codespace on the branch you intend to use. If the project contains a devcontainer.json file, GitHub uses its configuration to build the environment and install tools. Review that file before launching, especially post-creation commands that may run automatically. Do not execute setup from a repository whose source you do not trust.

Once the editor opens, use the terminal to run the project's usual checks, then use Git to commit and push changes to the branch. If your application exposes a local port, it appears in the Ports panel and can be opened in a browser preview. Start with a private port. Do not make a preview public merely for convenience: a public URL can allow anyone on the internet to reach the service.

Included usage: compute and storage

GitHub's billing page currently lists 120 hours of monthly compute time and 15 GB-month of storage for a personal GitHub Free account. GitHub Pro lists 180 hours and 20 GB-month. This included quota is for personal accounts; organization and enterprise plans do not receive the same free allowance. Once the quota is exhausted, creating or resuming billable environments may be blocked unless billing and budget settings permit additional use.

Do not treat compute hours as identical wall-clock hours for every machine size. GitHub explains that usage is measured with a multiplier based on processor cores: a two-core machine uses a multiplier of 2 for each active hour, while a four-core machine uses 4. A larger machine can therefore consume the included allowance faster even when it runs for the same amount of time.

Prices after the included quota

At the review date, GitHub's published list prices are $0.18 per hour for a two-core machine, $0.36 for four cores, $0.72 for eight cores, $1.44 for sixteen cores, and $2.88 for thirty-two cores. Storage is listed at $0.07 per GB-month. These are published USD rates; check the billing page and calculator because taxes, account policies, and future price changes can affect the final amount.

A simple example: ten hours on a two-core machine costs $1.80 before any included allowance is applied, while ten hours on a four-core machine costs $3.60. Do not forget storage. A stopped environment does not consume compute while stopped, but it continues to occupy storage until deleted. If you create many workspaces and forget them, storage can become the unexpected cost.

Stop the environment instead of only closing the browser tab

Codespaces uses a default idle timeout of 30 minutes, which you can change. GitHub's lifecycle documentation also describes a maximum lifetime of 12 hours before a codespace is automatically stopped. Closing the browser tab does not immediately stop the environment; processes may continue until the idle timeout is reached. Stop the Codespace manually from your Codespaces list when you finish working.

Stopped codespaces can be automatically deleted after 30 days of inactivity by default, and you can change the retention period. Save your work and push it to Git before deleting a workspace you no longer need. Deleting an environment slows future storage accumulation, but it does not necessarily erase usage that has already accumulated during the current billing cycle.

Security: secrets, repositories, and forwarded ports

GitHub says each Codespace runs on an isolated virtual machine and network, but the token assigned to the environment reflects your permissions on the repository. If you have write access, the token may have read/write access to that repository. Do not open unknown repositories, run setup scripts without review, or place API keys and passwords in configuration files or source code.

Use Codespaces Secrets for sensitive values and restrict which repositories can access them. Forwarded ports are private by default, but changing a port to Public means anyone on the internet can reach it without signing in to GitHub. Before changing visibility, make sure the service does not expose an admin panel, test data, or an internal-only interface.

A practical plan for controlling cost

Choose the smallest machine that fits the task, use the default image when it meets the project's needs, and limit extensions and large files that increase storage. Review the usage and billing pages regularly and configure a budget alert before you exceed your allowance. Stop the Codespace after each session, delete temporary environments you no longer need, and shorten the retention period if you create many test workspaces.

If your connection is unreliable, push changes to Git frequently. Codespaces is cloud-based, so you cannot continue working in the remote environment without internet access. Keep a local copy or use a local development container when offline work is important. The right choice is not the largest machine; it is an environment matched to the task, stopped when idle, and monitored for cost.

When Codespaces is a good fit

Codespaces works well for quick reviews, open-source contributions, trying a new branch, working from a device where you do not want to install development tools, or giving a team a consistent environment. It may be less suitable for continuous heavy computation, unstable internet connections, or projects that need local access to hardware and ports that a cloud environment cannot provide.

Before adopting it, test a small repository, inspect the devcontainer configuration, monitor usage, and verify that secrets and forwarded ports follow least privilege. If cost or connectivity is unsuitable, keep GitHub for source control and use a local environment or development container. The service is productive when managed; it is not a workspace to leave running without oversight.
